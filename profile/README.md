<p>从机房段换过来的人，通常会盯着"是不是住宅"这一条看，其实真正决定日常体验的是六七个参数：ASN 归属、类型标签、地址保持策略、单条并发上限、认证方式、开通方式、计费粒度。这些参数在报价单里往往被省略，问起来又各说各话。这篇按参数说明书的结构逐项写清：每个参数是什么、合格取值在哪、住宅代理和独享在哪些项上不同、接口批量开通要看哪几个字段，最后给一张可以直接拿去验收的取值表。</p>

<h2>一、六个必看参数，先说含义</h2>
<p>参数不需要全懂，但这六项直接对应钱和稳定性。看不懂参数就意味着没法比价，只能比销售的口才。下面逐项给出定义和查看方式。</p>
<h3>参数一至三：身份类</h3>
<p>ASN 归属指地址注册在哪个自治系统下，住宅宽带运营商与数据中心是两类。类型标签是情报库给出的分类，常见 residential、business、hosting、proxy。注册国家与城市决定登录地是否与账号资料自洽。前三项合起来回答一个问题：这条地址在平台眼里像什么。</p>
<h3>参数四至六：使用类</h3>
<p>地址保持策略指同一出口能固定多久，是会话级、日级还是月级。单条并发上限指一条地址允许几个同时连接。认证方式分账号密码、白名单 IP、密钥三种，影响批量管理的难度。这三项合起来回答：这条地址能怎么用、能几个人用。</p>

<h2>二、住宅代理和独享，差异集中在这几项</h2>
<p>这两个词经常被混着用，实际是两个维度的概念：住宅讲地址属性，独享讲使用独占。一条地址可以既是住宅又是独享，也可以是住宅但共享。比价时必须两个维度一起看，只看一个必然踩坑。</p>
<h3>差异一：地址保持策略</h3>
<p>典型的住宅代理池按会话分配，一次会话结束就换地址，保持时间从几分钟到几十分钟。独享住宅通常按天或按月锁定一条地址，长期不变。对需要维持登录记录的账号，后者明显更合适；对短时采集，前者成本低得多。</p>
<h3>差异二：并发与流量口径</h3>
<p>住宅代理池按流量计费为主，因为地址是共享的，没法按条计；独享按条计费为主，因为一条地址只给你。这两种口径不能直接换算，必须用真实流量样本折算成月度总价再比。</p>
<h3>差异三：开通与管理方式</h3>
<p>代理池通常提供统一的接口和网关，几百条会话通过一个入口调度；独享通常是一条一条开，逐条配置。团队规模上去之后，后者的手工成本会很明显，这也是接口批量开通存在的意义。</p>

<h2>三、接口批量开通要看哪几个字段</h2>
<p>几十条地址手工配一遍，出错概率很高，而且换人接手时没人说得清哪条对应哪个号。批量开通的意义不只是快，更是让配置可追溯。看接口文档时重点确认下面几项。</p>
<h3>创建与查询接口</h3>
<p>创建接口要能一次提交多条，返回每条的唯一标识；查询接口要能按标识查到当前出口地址、ASN、到期时间、使用状态。有这两组接口，才能把"地址台账"自动化维护起来，不用靠人肉记表格。</p>
<h3>批量操作与幂等</h3>
<p>批量续期、批量换址、批量停用这三类操作最好都有接口。另外确认接口是否幂等：同一个请求重复提交不会重复扣费、不会重复创建。没有幂等保证的接口，在网络抖动时容易开出多余地址。</p>
<h3>回调与额度控制</h3>
<p>地址即将到期、出口异常、额度不足这三类事件能否回调通知，决定了你能不能做自动告警。额度控制则要能设置单次批量操作的上限，防止脚本写错一次开出几百条。</p>

<h2>四、机房段和住宅段的参数差异</h2>
<p>机房段吃过亏的人对这段最有体会。两者的差异不在速度，而在身份类参数：ASN、类型标签、地理分布。速度上机房段通常更快，这正是它容易让人误判的地方。</p>
<h3>身份参数：一个像服务器，一个像家庭</h3>
<p>机房段的 ASN 指向云厂商或 IDC，情报库标 hosting；住宅段指向宽带运营商，标 residential。这个差异是结构性的，改不了。价格上机房段便宜很多，但用在需要长期身份的账号场景，省下的钱会在反复验证里还回去。</p>
<h3>性能参数：机房更快但抖动模式不同</h3>
<p>机房段延迟低且稳定，因为带宽充足、路由优化；住宅段延迟受家庭上行带宽和对端拥塞影响，波动更大。选住宅段时要接受这一点，重点看丢包和抖动，而不是只看平均延迟。</p>

<h2>常见问答</h2>
<h3>住宅代理和独享哪个贵？</h3>
<p>答：口径不同没法直接比。住宅代理按流量，用量小的时候总价低；独享按条按月，用量大时摊薄后更划算。判断方法是用自己一周的真实流量乘单价，和独享月费比。做长期登录的账号，即使独享贵一些也通常更合适。</p>
<h3>接口批量开通会不会导致地址被判定为机器注册？</h3>
<p>答：开通方式本身不是平台侧能看到的信息。真正会被观察到的是地址属性、并发特征和请求节奏。接口化只是管理手段，把开通做得规范、可追溯，反而能减少配置错误带来的异常。</p>
<h3>住宅段延迟高，能不能用中转加速？</h3>
<p>答：技术上可以，但要留意中转节点会改变链路特征，而且增加了故障点。多数情况下先把出口地区选对、把丢包压下来，比加中转更有效。确实需要中转时，选与出口同地区的节点，避免绕远。</p>
<h3>供应商给的参数和实测不一致怎么办？</h3>
<p>答：以实测为准，并把差异留存。ASN、类型标签、地址保持时长这三项都能自己验证。发现不一致时先沟通，沟通不成按合同条款处理。把每次验证结果存档，后续议价或换址时都有依据。</p>
